# DoReview

by Artem Dyakovich

Личный прогресс проверки кода для **PyCharm 2026.2**. Версия **0.2.11** сохраняет историю проверок и совмещает границы полосы DoReview с миникартой CodeGlance.

## Установка

1. Запустить `powershell -ExecutionPolicy Bypass -File .\build.ps1`.
2. В PyCharm открыть **Settings → Plugins → ⚙ → Install Plugin from Disk…**.
3. Выбрать `build/distributions/do-review-0.2.11.zip` и перезапустить IDE, если она предложит.

DoReview обновляет прежний Review Marks с сохранением истории и пользовательских сочетаний клавиш. Для совместимости сохраняются ID плагина `dev.reviewmarks` и идентификаторы действий `ReviewMarks.*`. Сборка не устанавливает плагин и не перезапускает рабочую IDE. Используется Java 25 из установленного PyCharm.

## Использование

**Ctrl+M** переключает проверку текущей строки или всех затронутых выделением строк. Полностью зелёный участок снимается; смешанный, жёлтый или непроверенный отмечается заново. Исходный код и выделение не изменяются.

Пустые строки и строки из одних пробелов или табов пропускаются, в том числе внутри выделения. Повторное Ctrl+M снимает проверку со всех выбранных непустых строк независимо от пустых промежутков. Прежние отметки на пустых строках больше не участвуют в подсветке или счётчике удалённых строк; история сохраняется. При очистке проверенной строки до пустой на ней не остаётся подсветки или маркера.

**Alt+M** переходит к следующей непроверенной непустой строке, **Alt+Shift+M** — к предыдущей, включая жёлтые. Курсор ставится в конец найденной строки. На границах файла поиск продолжается по кругу. Переход не меняет отметки. Оба сочетания назначены только открытому редактору поддерживаемого файла проекта: вне редактора сохраняются штатные действия IDE, включая Alt+M для Amend Commit. Назначенные пользователем сочетания Next/Previous Unreviewed Line также продолжают работать.

- **Зелёный:** текст проверен, соответствие однозначно, отслеживаемое структурное окружение совпадает.
- **Жёлтый:** текст прежний, но изменились условия/функция/цикл, участок перемещён или соответствие неоднозначно. Причина указана в подсказке.
- **Изменённая проверенная строка:** без зелёного фона, с маркером и переходом к сравнению. Новые строки начинают без отметки.

В строке состояния: **DoReview 76% · recheck 6**. Процент относится только к зелёным непустым строкам текущего файла; жёлтые требуют повторного просмотра. При удалении проверенного кода появляется отдельный счётчик **deleted**. Пустые строки не входят в знаменатель.

Меню **DoReview** содержит:

- **Toggle Reviewed** — то же действие, что Ctrl+M.
- **Clear Review in Selection** — явно снять проверку выбранных строк.
- **Next Unreviewed Line** — следующая непустая строка без подтверждённой зелёной отметки, включая жёлтые.
- **Previous Unreviewed Line** — предыдущая непустая строка без подтверждённой зелёной отметки, включая жёлтые.
- **Show Review Changes** — выбрать проверенную версию и открыть штатный diff с текущим текстом. Сравнение также открывается по клику на индикатор или маркер.
- **Attach Review History…** — вручную привязать историю отсутствующего файла после внешнего переименования.
- **Show DoReview Stripe** — показать или скрыть полосу DoReview во всех редакторах проекта.
- **Clear All Reviews in File** — отозвать все прежние проверки этого файла, сохранив историю.

## Полоса DoReview

Флажок **DoReview → Show DoReview Stripe** включает справа от редактора отдельную полосу шириной 14 логических пикселей. При видимой миникарте CodeGlance её отметки используют ту же геометрию, что и Git-маркеры миникарты: границы совпадают при прокрутке, сворачивании кода, мягких переносах и изменении масштаба. Без видимой миникарты полоса показывает сжатый обзор всего файла. По умолчанию она выключена; выбор сохраняется в workspace текущего проекта и действует во всех его редакторах, включая вложенные каталоги. Тот же флажок доступен по правому клику на самой полосе. Контейнер, Git-маркеры и настройки CodeGlance сохраняются; устанавливать CodeGlance для работы DoReview не обязательно.

Полоса показывает зелёные, жёлтые, изменённые и удалённые проверенные строки из той же проекции, что и подсветка. Соседние участки одного статуса объединяются. Пустые и непроверенные строки не создают отметок и разделяют участки. При наложении приоритет такой: удаление, изменение, жёлтый, зелёный. Клик или перетаскивание передаёт фокус редактору, ставит курсор на выбранную строку и центрирует её, как навигация по Git-маркерам CodeGlance. Колесо прокручивает редактор обычным способом. В разделённых редакторах каждая полоса использует геометрию своей миникарты либо собственный обзор файла.

## Изменения и ветки

Изменение кода не уничтожает свидетельство проверки. Возврат точного файла через Undo, смену ветки или внешнюю перезапись восстанавливает неотозванные отметки. Частичное совпадение восстанавливается только при однозначном сопоставлении.

Ручное снятие проверки сохраняется отдельно и имеет приоритет над восстановлением старого текста. Отзываются однозначно связанные прежние свидетельства выбранных строк; неоднозначные кандидаты не отзываются за соседние строки. Команда Clear All отзывает все прежние проверки файла. Новая явная проверка через Ctrl+M снова разрешена.

При локальных вставках координаты редактора сохраняют идентичность прежних строк: вставленная копия не получает отметку оригинала. После внешних изменений неоднозначные одинаковые строки требуют подтверждения. Пробелы, комментарии и завершающий перевод строки значимы; CRLF приводится к представлению LF редактора.

Если происхождение строки уже потеряно, возврат её точного текста в новой внешней версии требует подтверждения: это жёлтый статус неоднозначного соответствия. Совпадение с исходным текстом внутри расширившегося диапазона изменений не должно само по себе давать маркер «текст изменён».

В 0.2.8 исправлен перенос состояния при загрузке ещё не виденной версии файла: известные координаты временно изменённой строки допускают повторное сопоставление, если в сохранённой версии нет другой строки с её точным исходным текстом. Возврат точного текста и контекста позволяет восстановить зелёный статус при однозначном сопоставлении. Защита известных вставленных копий и ограничения после потери происхождения, удаления или разделения строки сохраняются. Уже записанные прежней версией неоднозначные отметки нужно просмотреть и подтвердить вручную через Ctrl+M. В 0.2.11 их автоматическое восстановление или очистка не выполняется.

Сложные соответствия строк сохраняются как служебные подсказки, привязанные к хешу текущего текста. Закрытие редактора и перезапуск IDE не должны превращать известную вставленную копию в проверенный оригинал. Эти подсказки не создают свидетельств проверки и не меняют сохранённую историю.

Ветви одного рабочего каталога используют общую личную историю. Разные проекты и worktree независимы. Удаление файла не удаляет историю; его возвращение позволяет восстановить проверку. Переименование в IDE переносит связь автоматически. Внешнее переименование требует ручной перепривязки; другой файл с тем же содержимым не получает чужие отметки.

## Структурное окружение

Адаптеры используют PSI языковых плагинов:

- **Python:** модуль Python в PyCharm.
- **Tact:** Intelli Tact, API версии 0.1.2.
- **Tolk:** TON plugin, API версии 4.1.0.

Отслеживаются заголовки объявлений, условия, циклы, роли веток и содержащая их цепочка. Тело функции целиком не является отпечатком: обычная правка соседнего оператора не сбрасывает весь блок.

Для Tact `asm fun` контекстом служат заголовок и всё тело assembly-функции. Неизменённый проверенный asm сохраняет зелёную отметку; изменение любой инструкции требует перепроверки всего этого объявления, поскольку зависимости стека и переходы внутри asm не анализируются.

Внутри блока также учитываются предшествующие явные проверки (`require`, `assert` и известные встроенные проверки языка) и конструкции с ранним выходом. Изменение их условий требует перепроверки последующих строк. Произвольные вызовы не считаются проверками по похожему имени. Это ограниченный синтаксический анализ; произвольный поток выполнения не вычисляется.

Языковые зависимости optional. Для неподдерживаемого языка контекстом становится весь снимок файла: после его изменения прежние неизменные проверенные строки жёлтые, а возврат точного снимка восстанавливает их. При ошибке разбора неопределённая область также жёлтая до надёжного пересчёта.

Ошибка в следующем объявлении Tact/Tolk не делает жёлтыми предыдущие самостоятельно закрытые объявления с корректным PSI. Их строки всё равно сравниваются с проверенным текстом и контекстом. Незакрытое тело, ошибка внутри объявления или в содержащем его заголовке остаются неопределёнными; строка с посторонним кодом после закрывающей скобки также не получает это исключение.

Для Tact поддерживается также изоляция обработчиков ниже опечатки вида `receive(...)a {`. Установленный lexer подтверждает баланс скобок и завершённость строк/комментариев; официальный PSI-парсер однократно повторяет разбор служебной копии с лишними идентификаторами заголовка, заменёнными пробелами. Повреждённый обработчик целиком остаётся жёлтым. Нижний может быть зелёным только при подтверждённых границах, прежнем тексте и прежнем контексте. Скобки внутри строк и комментариев не считаются структурными. При незакрытых скобках отдельный узел, восстановленный парсером ниже, сам по себе не подтверждает проверку. Исходный документ не исправляется.

Подсветка подтверждает неизменность прочитанного текста и отслеживаемого синтаксического окружения. Анализ значений переменных, влияния вызовов и зависимостей не выполняется, в том числе между функциями одного файла.

## Хранение и миграция

История хранится локально в конфигурации IDE, в **review-marks-history.xml**, отдельно от Git рабочего каталога. Она содержит снимки исходного текста, свидетельства проверки и отзывы. Settings Sync для этого хранилища отключён. Снимки дедуплицируются; автоматической очистки истории нет.

DoReview 0.2.11 использует прежнюю схему журнала 2, введённую в версии 0.2.2. Обновление сохраняет формат свидетельств и отзывов, а также расположение XML-журнала. Буквальные строки вроде `$USER_HOME$` хранятся без подстановок IDE. Схема 1 читается с проверкой исходных хешей; неподтверждённые повреждённые данные не дают зелёных отметок. Версии со старой схемой не смогут записывать новое хранилище.

Служебный кеш checkpoint имеет отдельную версию: начиная с 0.2.8 записывается v2 с разрешением `allowRematch`; в 0.2.11 этот формат прежний. Записи v1 читаются с прежним каноническим checksum; без полного текста сохранённой версии их ограничения сохраняются консервативно. При возврате к 0.2.7 кеш v2 не прочитается и возможны жёлтые статусы; журнал свидетельств и отзывов сохраняется.

Старый `.idea/review-marks.xml` импортируется один раз **из сохранённого текста**, до сопоставления с открытой веткой. Исходный файл не перезаписывается; его резервная копия находится в каталоге конфигурации IDE, **review-marks-legacy-backups**. Повреждённые записи не превращаются в подтверждённые отметки.

Поддерживаются локальные текстовые файлы внутри проекта. Бинарные файлы, scratch, внешние каталоги и редакторы diff не размечаются. Плагин не изменяет исходники и не отправляет код в сеть.

## Разработка

Границы компонентов, потоки, инварианты доверия и пределы масштабирования описаны в [архитектуре](docs/ARCHITECTURE.md). Команды проверок и порядок выпуска — в [инструкции по проверке](docs/VALIDATION.md).

```powershell
.\build.ps1
.\build.ps1 -Tasks runIde
.\build.ps1 -IdePath 'D:\Apps\PyCharm 2026.2'
```

Проверки: core, реальные PSI-адаптеры, интеграция редактора, история, миграция и Git-переходы. Команды Gradle: `check buildPlugin verifyPluginStructure`.

Для отдельной проверки совместимости с установленным CodeGlance укажите путь к его каталогу. Этот параметр подключает плагин и дополнительные тесты только к тестовому запуску; обычная сборка не требует CodeGlance:

```powershell
.\build.ps1 -Tasks @(
    "-PcodeGlancePluginPath=$env:APPDATA/JetBrains/PyCharm2026.2/plugins/CodeGlancePro",
    'test', '--tests', 'dev.doreview.ide.ReviewStripeCodeGlanceTest'
)
```

Дополнительная матрица на внешней копии Tact-контрактов включается параметром Gradle `-PreviewCorpus=D:/Disposable/ContractCopy`, переданным внутри `-Tasks`. Нужна полная копия набора из семи `.tact` файлов; исходный каталог не изменяется. Команда и требования к входному набору приведены в [инструкции по проверке](docs/VALIDATION.md). Без параметра `reviewCorpus` матрица не запускается.

Критерий приёмки: в конечной матрице правок нет ложных зелёных отметок; заведомо новые строки не наследуют проверку; однозначно неизменённые экземпляры строк с прежним отслеживаемым окружением сохраняют её. Проверяются вставки и дубликаты, разделение и склеивание строк, удаления, условия, циклы, функции, обработчики, ошибки PSI, Undo/Redo, возврат Git-версий, сериализация истории и ручной отзыв. Отдельные регрессии проверяют неоднозначность, лимиты, отсутствие языкового плагина и согласованность интерфейса. Матрица фиксирует проверенные сценарии, а не доказывает семантическую эквивалентность программ.

Совместимость ограничена платформой **262 (2026.2)**. Для воспроизводимой сборки зависимости парсеров закреплены; локально используются установленные совместимые плагины.
