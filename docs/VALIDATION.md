# Проверка и выпуск DoReview

by Artem Dyakovich

Команды выполняются в корне репозитория через PowerShell. Нужны PyCharm 2026.2 с Java 25 и Git в `PATH`. `build.ps1` находит локальный PyCharm либо принимает его каталог через `-IdePath`. Сборка использует закреплённые версии языковых плагинов; их источники и варианты локального подключения заданы в [build.gradle](../build.gradle).

## Основной прогон

```powershell
.\build.ps1 -IdePath 'C:/Program Files/JetBrains/PyCharm 2026.2'
```

По умолчанию выполняются `check buildPlugin verifyPluginStructure`: IDE / JUnit тесты, самостоятельные проверки ядра, изолированная компиляция ядра, сборка ZIP и проверка структуры плагина. Отчёт JUnit находится в `build/reports/tests/test/`, XML — в `build/test-results/test/`, архив ручной установки — в `build/distributions/`.

Для отдельного теста передайте все аргументы Gradle через `-Tasks`:

```powershell
.\build.ps1 -Tasks @('test', '--tests', 'dev.doreview.ide.DoReviewServiceTest')
```

## CodeGlance

Дополнительный набор `ReviewStripeCodeGlanceTest` содержит восемь проверок с настоящим CodeGlance: координаты Git-маркеров миникарты, режимы рендеринга и масштаб, split editors, folding, soft wraps, block inlays, навигация, обновление настроек и снимок интерфейса. Для него нужна установленная совместимая копия CodeGlance. Укажите каталог плагина:

```powershell
.\build.ps1 -Tasks @(
    "-PcodeGlancePluginPath=$env:APPDATA/JetBrains/PyCharm2026.2/plugins/CodeGlancePro",
    'test', '--tests', 'dev.doreview.ide.ReviewStripeCodeGlanceTest'
)
```

Параметр подключает локальный плагин и `src/codeGlanceTest/java` к тестовому запуску. Основной прогон выполняется без этого параметра; обычная установка DoReview не требует CodeGlance.

## Внешние Tact-контракты

`ContractCorpusAuditTest` включается отдельно. Подготовьте одноразовую полную копию входного набора из **семи `.tact` файлов**, включая вложенные каталоги. Тест сортирует файлы по пути и выбирает контракты по индексу; произвольные семь файлов могут не содержать нужных конструкций. Исходники читаются в тестовые файлы с обезличенными именами; исходная копия не редактируется.

```powershell
.\build.ps1 -Tasks @(
    '-PreviewCorpus=D:/Disposable/ContractCopy',
    'test', '--tests', 'dev.doreview.ide.ContractCorpusAuditTest'
)
```

Без параметра `reviewCorpus` этот набор исключён из обычного прогона. Проверяются изменения текста и контекста, дубликаты, вставки и удаления, повреждение PSI, Undo/Redo, Git-переходы, перезапуск хранилища и ручной отзыв. Матрица проверяет отсутствие ложных зелёных отметок в своих сценариях; она не доказывает семантическую эквивалентность программ.

## Ручная проверка интерфейса

В отдельной тестовой IDE выполните `runIde` либо установите собранный ZIP через **Install Plugin from Disk…**:

```powershell
.\build.ps1 -Tasks runIde
```

- Проверьте Ctrl+M, снятие отметок, пустые строки, переходы Alt+M / Alt+Shift+M, сравнение версий и счётчики. Новая строка не должна наследовать зелёную отметку.
- Проверьте правку и возврат текста, Undo/Redo и `git pull` в одноразовом репозитории. До актуального расчёта прежняя зелёная подсветка должна исчезать.
- Включите Show DoReview Stripe во всех редакторах проекта, включая вложенные каталоги; проверьте независимость другого проекта и сохранение настройки после перезапуска.
- С CodeGlance сравните границы полосы с его миникартой и Git-маркерами при прокрутке, изменении размера, folding, soft wraps и масштабировании. Проверьте клик, drag, колесо и изменение настроек CodeGlance. Без CodeGlance должен работать обзор всего файла.
- Проверьте split editors, позднее открытие файла, повторные включения и выключения полосы, закрытие редакторов. Пустые промежутки должны разделять отметки; при наложении приоритет: удаление → изменение → перепроверка → проверено.

## Выпуск и локальные результаты

Обновите версию сборки, дескриптор плагина и документацию согласованно. После окончательных правок выполните основной прогон, затем необходимые дополнительные проверки. Проверьте версию ZIP, содержимое архива и ручную установку. Сборка сама не устанавливает плагин и не перезапускает рабочую IDE.

Логи, машинные отчёты и снимки интерфейса сохраняйте под `build/`; этот каталог исключён из Git. Разовые отчёты выпусков хранятся локально в `docs/local-validation/` и также не входят в репозиторий. В Git поддерживаются эта инструкция и [описание архитектуры](ARCHITECTURE.md).
